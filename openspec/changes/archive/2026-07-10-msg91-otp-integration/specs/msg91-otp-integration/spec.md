## ADDED Requirements

### Requirement: MSG91 OTP Delivery Hook
The system MUST route all SMS OTP delivery requests generated by Supabase Auth through MSG91's v5 API instead of the native Twilio integration.

#### Scenario: Send OTP on Login/Signup
- **WHEN** a user initiates a login or signup with a phone number
- **THEN** Supabase Auth generates a one-time password and intercepts the delivery using the configured `send_sms` hook pointing to our Deno function, which format-converts the payload and successfully dispatches it using the MSG91 API.

#### Scenario: Validate Payload and Send to MSG91
- **WHEN** the Send SMS Hook receives a POST payload from Supabase GoTrue
- **THEN** it validates that both a phone number and an OTP code exist in the payload, formats the phone number to be compliant with MSG91 (removes leading `+`), and calls MSG91's POST API at `https://control.msg91.com/api/v5/otp` with the correct `authkey`, `template_id`, and `otp` body parameter.

#### Scenario: Handle MSG91 API Failures
- **WHEN** MSG91's API returns a non-200/non-success response status
- **THEN** the Send SMS Hook logs the failure details and returns a `502 Bad Gateway` status to Supabase GoTrue to indicate that OTP dispatch has failed.
